README.md / 給每個正在和 AI 一起寫 code 的團隊

AI 寫 code 很快。
靠流程，才能走得更遠。

所以我把任務、同步、review、記憶和交接串成一套 skill。 Notion 留下我們要做什麼、做到哪裡；GitHub 留下程式怎麼改、怎麼交付。 兩條路接在一起，從討論到交接，每一步都有脈絡可循。

WHY · 先不是功能，是我們真的遇過的事

AI 已經會寫了，為什麼團隊還是會卡住？

因為工作不會停在「code 生出來」那一刻。當它要跨過好幾個視窗、好幾天，最後交到另一個人手上時，麻煩才慢慢跑出來。

×

改動突然不見

AI 很聽話，但一句「幫我處理」可能讓它選到最快、也最危險的解法。

review 開始塞車

code 一下子變多了，真正需要判斷的地方反而更難被看見。

A…?

換個 session 就斷線

昨天談過的取捨、還沒回答的問題，今天又得重新猜一次。

???

任務還停在昨天

repo 裡其實做完了，但團隊看的任務頁沒有結果，也不知道怎麼接。

CORE · 我想做的，不是再加一份規定

把協作變成 AI 真的走得完的路。

✦團隊的工作流裝在 AI 身上
靠流程，不靠誰剛好記得

開工、驗證、交接都有下一步。

不只把事情做好，也交付好

為多人、多天、多視窗留下接手點。

skill 彼此接得起來

不是怪人或怪 AI，而是回頭改護欄。

跨工具，但脈絡不斷掉

WHY · 一份工作，兩條都要接得上的路

工作從哪裡來，結果就回到哪裡。

需求先進 Notion，帶著背景到 repo 裡工作。GitHub 接住程式的同步、檢查與交付，最後把結果帶回原本的任務。

會會議／需求一句承諾先有出處

→/sync-report

⑂GitHub在 repo 工作時，也接上團隊的程式進度
↻開工同步/sync

⑂commit／PR/wrap-up
