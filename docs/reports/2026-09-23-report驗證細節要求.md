# Report 驗證細節要求

# Description

- Sparktoy B4 wrap-up 首版報告依 `report` skill 的「每節 1–3 句」規則壓縮過度，使用者無法從報告判斷實際完成內容，並再次要求補足 verification。這表示原規則對非簡單功能缺少依工作規模調整篇幅的要求。

# Changes Made

- `skills/report/SKILL.md` 將固定篇幅限制改為依工作規模決定細節。功能開發必須按行為與實作區域說明，並要求 verification 留下指令或手動情境、代表輸入、預期與實際結果，以及刻意未執行的範圍。
- `skills/report/templates/report-task.md` 新增明確的 `# Verification` 區段，避免測試證據只剩一句成功／失敗；`# Result` 改為聚焦使用者可見結果與限制。
- `skills/wrap-up/full.md` 在 report handoff 明定沿用 `/verify` 證據，非簡單功能不能只寫「tests passed」。

# Verification

- `git diff --check -- skills/report/SKILL.md skills/report/templates/report-task.md skills/wrap-up/full.md docs/reports/2026-09-23-report驗證細節要求.md` — 確認新增文字沒有 whitespace error。
- 人工檢閱三個規則入口：報告生成流程、Task Report 模板、Full wrap-up report handoff，確認詳細驗證要求不依賴單一入口才會生效。
- 本次只改 Markdown workflow 指令，沒有可執行程式或 runtime test。

# Result

- 後續非簡單功能的報告會保留足以審核的行為變更與驗證證據；小型修改仍可維持簡短，不會被迫產生冗長報告。
