# Review checklist

These are the project-specific checks. General quality is handled by `impeccable detect` (every version, mechanical: contrast, banned patterns, spacing, type) and `impeccable critique` (the version the user leans to, judgment: heuristics, hierarchy, cognitive load). Judge these before reading detector output.

| Pass | Check |
|---|---|
| Flow | Every acceptance criterion in `brief.md` can be completed, including its exceptions (empty data, invalid input, no permission, going back) |
| Brand | Each rule in `brief.md` passes or fails individually |
| Peak moment | The version's named peak moment actually lands |
| Distinctness | Swap the headlines between two versions — if nobody would notice, they are too similar; no two share a layout (see [style-guide.md](style-guide.md)) |

Mark each item pass / fail / can't verify, with the screenshot it rests on. Report separately what you saw in the browser, what you only read in code, and what you didn't test.
